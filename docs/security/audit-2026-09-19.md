## Findings

No **Critical** findings (nothing secret in the repository or its history).

| # | Severity | Finding | Resolution |
|---|---|---|---|
| H1 | High | Cost abuse: anonymous `POST /batches` could write ~500 DynamoDB items per call at 10 rps; `POST /runs` had only a concurrent cap | **Fixed**: atomic hourly limits (runs 30, races 30, batches 20, experiments 60 → 429); concurrent runs capped at 3 (409) |
| H2 | High | No security headers on the site; an inline theme script would break under a CSP | **Fixed**: CSP, HSTS, nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options via Amplify `customHttp.yml`; theme bootstrap moved to a file |
| H3 | High | Deploys use the AWS account root user | **Owner action**: enable MFA on root; deploy with an IAM Identity Center user |
| M1 | Medium | Loose request validation: unknown fields ignored, 1 MB bodies, permissive names and IDs | **Fixed**: strict schemas in `domain/requests.py`; 256 KB cap; ID and name rules |
| M2 | Medium | Run failure messages stored raw Lambda error text (could include ARNs or table names) | **Fixed**: only the error type is stored; details stay in CloudWatch |
| M3 | Medium | Receipts bucket: versioning off, no TLS-only policy | **Fixed** |
| M4 | Medium | No API Gateway access logging | **Fixed**: JSON access log (request ID, IP, route, status, latency; never bodies) |
| M5 | Medium | Unpinned backend dependencies; no Dependabot or security scans in CI | **Fixed**: exact pins, Dependabot (pip, npm, actions), CI gitleaks, pip-audit, npm audit, checkov |
| M6 | Medium | No security tests | **Fixed**: 27 unit-level negative tests; `security_smoke.py` against the deployed stack |
| L1 | Low | PITR off | **Fixed** on every table that holds data |
| L2 | Low | Log retention 14 days | **Fixed**: 7 days (see the correction below) |
| L3 | Low | CORS also allowed `localhost:4173` | **Fixed**: Amplify site and `localhost:5173` only |
| L4 | Low | Active-run cap 2 | **Changed** to 3 per the brief (see the correction below) |
| L5 | Low | `.gitignore` gaps (`*.pem`, `dist/`, local samconfig) | **Fixed** |
| L6 | Low | No lint rule against `dangerouslySetInnerHTML` | **Fixed** (also `eval`, `new Function`) |
| L7 | Low | Evidence drawer shows ARNs containing the account ID | **Accepted**: by design, not in error bodies; account IDs are not secrets |
| L8 | Low | No `SECURITY.md`, threat model or ADR | **Fixed** |

## Already compliant before the pass

Stage throttling 10/20 applied; error bodies `{code, message, request_id}` with no stack traces; per-function least-privilege roles with no admin policies; SQS SSE; S3 Block Public Access and SSE-S3; fonts self-hosted from our origin; no third-party scripts or outbound calls; only `VITE_API_URL` in the browser; no delete endpoints; seeded demo data cannot be overwritten.

## Correction (19 Sep 2026, later the same day)

L2 and L4 changed the template defaults, but the deployed stack kept its earlier values (14 days, cap 2). When a parameter is not passed, `sam deploy` reuses the value the stack already has. `backend/samconfig.toml` now pins `MaxActiveRuns=3` and `LogRetentionDays=7`, and the stack was redeployed. Verified on AWS afterwards: all four log groups keep logs for 7 days, and the stack parameter `MaxActiveRuns` is 3.
